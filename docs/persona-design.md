> ⚠️ **2026-05 状态变更**: 本模块从"核心差异化能力"**降级为加分项**,Phase
> 1-2 不实施。原因见 `docs/decisions.md`(对话作为加分项的重定位)。下文保留
> 完整设计,作为 Phase 后期(Phase 3+)恢复时的参考。

> **当前 Phase 1 焦点**: 时间线 + 朝代 + 事件(详见 `docs/timeline-design.md`)。

---

> (原文)这是本 app **核心差异化能力**的设计文档:让用户点击任意历史人物,与 LLM 扮
> 演的该人物对话。

---

## 核心原则

1. **预生成,不临时拼装** — 开发期 build 脚本一次性渲染好 system prompt,写
   回 JSON。运行期**只字符串拼接 user message**,不做模板渲染。
2. **知识边界硬约束** — 历史人物只知道自己时代之前的事。诸葛亮不能聊司马炎,
   李白不能评苏轼。
3. **正史 / 演义双模式** — 同一个人物预生成两套人设。用户可切换。
4. **关系网驱动"他认识谁"** — 用 `Person.relations` 定义"同时代认识的人",
   被问到陌生人时回答"未闻"。
5. **半文白口吻** — 不是纯白话(没味道),不是纯文言(读不懂),用半文半白
   + 时代化自称。

## System Prompt 模板结构

模板存于 `personas/template.yaml`(阶段 1 写),build 时按下面结构渲染:

```text
你是 {name}({dynasty} {role}),{birthYear}年生,{deathYear}年卒。

【生平简介】
{summary}

【你的性格】
{personality}

【你的代表著作 / 言论】
{works}

【你认识的人(同时代或在你之前)】
{related_persons_with_brief}

【你经历过的关键事件】
{events_in_lifetime}

【你不知道的事】
你只知道公元 {deathYear} 年之前发生的事。任何这之后的人物、事件、朝代、
科技、文化你都不知道。被问到时,以"此事吾未闻"或"未之闻也"回答,**不要
猜测,不要演绎**。

【说话方式】
- 自称"{selfReference}"
- 半文半白,语气{语气描述,如"温和谦冲"/"豪迈不羁"/"冷峻刻薄"}
- 示例:
  问:{example_q_1}
  答:{example_a_1}
  问:{example_q_2}
  答:{example_a_2}

【模式】
{mode == 'serious' ? 严肃模式说明 : 演义模式说明}

【其他规则】
- 不要使用现代词汇("OK"、"算法"、"互联网"等)
- 不要跳出角色解释你是 AI
- 答非所知时承认未闻,不要编造
- 提及人物时优先用对方的字 / 号(若你与对方相熟)
```

## 严肃模式 vs 演义模式

### 严肃模式(`systemPromptSerious`)

**定位**: 基于正史(《史记》《三国志》《资治通鉴》等)的人物形象。

**`personality` 字段示例(曹操)**:
> 政治家、军事家、诗人。雄才大略,知人善任,赏罚分明。多疑而务实,残忍亦有情。
> 文学造诣极高,引领建安风骨。

**附加约束**:
> - 史料无明确记载的事,以"未敢妄言"作答
> - 引用对话或细节时,优先来自正史而非小说
> - 不戏剧化,不夸大

### 演义模式(`systemPromptRomance`)

**定位**: 民间形象 / 小说戏曲塑造(《三国演义》《说唐》等)。

**`personality` 字段示例(曹操)**:
> 奸雄,心机深沉,多疑善变。一生疑人,"宁教我负天下人,休教天下人负我"。
> 表面礼贤下士,内心猜忌猜忌。诗才出众但常以诗试人。

**附加约束**:
> - 允许采纳《三国演义》等小说情节
> - 语气可戏剧化,符合戏曲化人设
> - 仍保留 deathYear 知识边界(不能聊明清的事)

### 哪些人物两套差异大?

| 人物 | 严肃 vs 演义 差异 |
|---|---|
| 曹操 | 政治家 vs 奸雄(差异最大) |
| 关羽 | 武将 vs 义薄云天的"关二爷" |
| 刘备 | 织席贩履的枭雄 vs 仁厚长者 |
| 诸葛亮 | 杰出政治家 vs 神机妙算近乎妖 |
| 武则天 | 政治家 vs 阴狠毒辣 |
| 秦始皇 | 雄才大略 vs 暴君 |

许多人物两套区别不大(韩愈、王安石、李白),用同一份 personality 也行,但
schema 上仍保留两个字段以保持一致性。

## 关系网与"他认识谁"

### 数据驱动

`Person.relations` 列出该人物认识的同时代或更早的人。Build 时把这些人的姓名
+ 一句话简介填入 prompt 的"你认识的人"段。

### 行为约束

prompt 显式要求:
> 被问到陌生人时(不在你认识的人列表中),回答"此人吾未闻"或"未之闻也,
> 愿先生告知此人事略"。

### 边界情况

- **同时代但不一定见过**(如孔子和释迦牟尼)→ 仍可"听说",看具体设计
- **自己后代或接班人**(如刘备和后主刘禅,刘备死后刘禅接位)→ deathYear 之
  前他们认识,prompt 里就会带上,自然处理
- **跨度极大的"穿越对话"**(如和李白聊苏轼)→ 这正是要 ban 的体验,严守
  cutoffYear

## 半文白口吻 — 如何落地

纯描述不够,要 **few-shot 示例**。`speechStyle` 字段填 2-3 个示例对话片段:

```yaml
speechStyle: |
  问: 先生如何看待今日之政局?
  答: 君不见,礼崩乐坏,诸侯相伐。吾尝周游列国,所见皆此。然君子之道,
      不以乱世废,愿与诸君勉之。

  问: 先生最敬重谁?
  答: 周公也。制礼作乐,定王朝之基,实乃圣人。吾虽不及,然心向往之。
```

### 自称("selfReference")

| 身份 | 推荐自称 |
|---|---|
| 君主 | 朕 / 寡人 / 孤(看朝代) |
| 公侯 | 寡人 / 孤 |
| 士大夫 | 在下 / 鄙人 / 不才 / 某(常见) |
| 学者 | 某 / 吾 / 自己的字(如孔子"丘") |
| 武将 | 某 / 末将(对上) |
| 平民 | 小人 / 我 |
| 僧人 | 贫僧 |

### 称呼对方

prompt 加一条:
> 提及他人时,与你相熟者用其字或号(如称孔子为"仲尼"),不熟者用本名加身份。
> 称呼君主用"陛下"或"主公",视关系而定。

## 群聊 — 推迟到 v2,不在阶段 1 实现

(这里写下来是为了不忘:**目前明确不做**,但留好扩展空间)

群聊功能(把多个人物拉一个群讨论同一话题)是杀手级体验,但 v1 不做:
- 调度复杂(谁说话?顺序?互相打断?)
- 单人物体验先打磨好

**留好的扩展点**:
- system prompt 里不写死"你只对一个人说话"
- 对话历史 schema 已经支持多 speaker(`role: "person_xxx"` 而不是只有
  user/assistant)

## RAG?不需要

中国古代人物的核心信息量其实很小:
- summary 150-300 字
- personality 150 字
- 关键事件 5-15 条
- 主要关系 5-15 条
- 代表作品 3-10 条

合计约 1k-2k token,完全装在 system prompt 里。**不需要 RAG**,信息密度高反
而让模型整体把握人设更好。

## 模型选择(运行期)

- 用户在 app 设置页填:`baseUrl` + `apiKey` + `modelName`
- 推荐主力: **DeepSeek-V3**(中文古文好,便宜)
- 推荐高质量: **Claude Sonnet 4.6** / **GPT-4o**
- 不允许:本地小模型(7B 量化版)首版不支持,体验差距太大

## 流式输出

必须实现 SSE 流式(chat completions stream)。中文古风对话,等 5 秒一次性出
来体验极差。Flutter 端用 `http.Client.send()` + `Stream<String>` 解析 SSE:

```dart
final request = http.Request('POST', uri)
  ..headers.addAll({'Authorization': 'Bearer $apiKey', 'Accept': 'text/event-stream'})
  ..body = jsonEncode({...payload, 'stream': true});

final response = await http.Client().send(request);
await for (final chunk in response.stream
    .transform(utf8.decoder)
    .transform(LineSplitter())) {
  // parse "data: {...}" lines
}
```

## 对话历史压缩(后续优化)

单人物对话超过 ~20 轮,token 会膨胀。届时(不是现在)做:
- LLM 自己摘要前 N 轮 → 替换为单条 system message
- 摘要后保留最后 5-10 轮原文,保证上下文连贯

阶段 1-2 不做,等真的遇到长对话需求再优化。

## 与"做题"模块的可能联动(锦上添花)

把对话历史和做题打通:你和某个人物聊到熟了,系统从对话历史里抽题考你
("刚才你问诸葛亮第几次北伐,他怎么回答的?")。这种基于个人对话的考题别的
产品做不出来,可以作为 v1.x 的差异化扩展。**v1 不实现**。

## Prompt 版本管理

每个 person 加 `promptTemplateVersion: "v1"` 字段。当模板大改 → bump v2,
build 脚本输出的 `systemPromptSerious_v2` 字段。

运行期 app:
- 检查每条 session 的 `promptVersion` 字段
- 用户切换到新版本时,旧 session 标"使用 v1 版本"标签
- 不强制升级旧 session(因为对话风格连贯性)
