## 双层风格

每个 event 同时有 `summary` (A 风格) + `body` (C 风格),职责互补。

### A 风格 — `summary` 字段

```
   特征:    教科书味,精准,可背诵
   字数:    150-500 字(常态 200-300)
   用途:    树图卡片快速浏览
   语言:    中性,不带情感色彩
   结构:    1-2 段陈述,无 markdown 标题
   动词:    "击败" / "建立" / "标志" 等中性
```

**示例(武王伐纣)**:
```
   公元前 1046 年,周武王姬发率诸侯联军于牧野(今河南淇县境内)击败商纣王
   军队。商军临阵倒戈,纣王自焚于鹿台,商朝灭亡。武王建立周朝,定都镐京,
   后由周公制礼作乐,开启了影响中国 3000 年的宗法封建秩序。
```

**反例(不要这样写 summary)**:
- ✗ "那个年代的故事让人感慨..."(情感化)
- ✗ "武王伐纣是中国历史上最重要的战役之一"(主观评价)
- ✗ "公元前一千多年前..."(年份不精确)

### C 风格 — `body` 字段

```
   特征:    历史叙事,故事感,可读
   字数:    800-2000 字(常态),5000 字硬上限
   用途:    详情页深度阅读
   语言:    生动但克制,不编对话/天气/具体细节
   结构:    必含 `## 起因` / `## 经过` / `## 后果` 三段
            可扩 `## 影响` / `## 评价` / `## 争议`
   后果段:  必须含**现代史学视角**("传统认为...,但当代研究表明...")
   动词:    叙事性("武王选了商朝最虚弱的时刻") + 时态明确
```

**示例**: 见 `docs/decisions.md` ADR-025 的武王伐纣完整示例。

**关键约束**:
- ✗ 不编造具体细节(没记载的天气、对话、人物心理)
- ✗ 不戏说(把历史当小说写)
- ✗ 不带政治价值判断(尤其敏感时段)
- ✓ 可重组叙事顺序使其有张力
- ✓ 可引用考古发现 / 现代史学家观点
- ✓ 后果段链接到当代("这套秩序至今影响中国人")

## 内容比例(每朝代 100 件事件)

```
                 教科书默认  本项目目标   理由
                 ────────    ─────────    ──────────────────
   政治            40%        25%         "皇帝换了"事件少,关键转折保留
                                          (商鞅变法 / 王安石变法 / 玄武门之变)

   军事            25%        15%         决定性战役保留(赤壁/淝水/萨尔浒)
                                          番夷讨伐 / 例行边患砍掉

   文化            15%        25% ★       诸子百家 / 三教合流 / 唐诗宋词
                                          ★ 趣味性最高的类别

   科技            5%         15% ★       张衡地动仪 / 蔡伦造纸 / 沈括梦溪
                                          ★ "中国发明史" 趣味爆表

   外交            5%         5%          张骞 / 郑和 / 王玄策(有故事的留)

   经济            5%         5%          土地制度 / 钱币演变(标志事件)

   人物大事        5%         10%         孔子诞 / 司马迁写史记 / 玄奘西行
                                          ("个人英雄时刻"教科书少提)
```

**LLM 起草 prompt 模板**:
```
   为<朝代>列出 100 个最关键事件,要求:
   - 政治军事合计不超过 40%(传统课本约 65%)
   - 文化 + 科技 + 人物 至少占 50%
   - 优先选**有故事可讲**的(人物冲突 / 戏剧性转折 / 出乎意料)
   - 教科书必考的也要留(高中史的基线)
   - 每条事件给出 1 句话理由说明为什么"关键"
   返回 JSON 数组,每条含 name / year / category / summary 5 字 / 入选理由。
```

## "关键事件"入选标准

```
   一个事件值得入选,如果至少满足 2 条:
   ────────────────────────────────────────────────────
   ✓ 高中历史教科书出现过(基线)
   ✓ 影响延伸到当代("分封制""科举""王朝周期律"现在还讨论)
   ✓ 朋友圈普通人都听说过("商鞅变法""玄武门之变")
   ✓ 改变了某种结构/制度(政治 / 经济 / 思想)
   ✓ 有戏剧性故事(冲突 / 反转 / 悲剧)
   ✓ 冷知识趣味强(沈括发现磁偏角 / 张衡测地震 1500 公里外)

   一票否决:
   ────────────────────────────────────────────────────
   ✗ 只是"年号变了""皇帝死了"无后续
   ✗ 民族讨伐之类细节(整个时段合并为 1 条概要)
   ✗ 党争内斗细节(只留转折点,不留每一回合)
```

## 政治敏感边界

```
   安全话题(随便挖,鼓励现代视角)
   ──────────────────────────────────────────
   • 商朝灭亡的内因 vs "暴君叙事"
   • 秦始皇的"暴政"标签 vs 制度奠基者
   • 隋炀帝的"昏君"形象 vs 开科举/通运河
   • 宋朝"积弱"叙事 vs 经济文化巅峰
   • 明朝"闭关锁国"修正 vs 实际朝贡贸易
   • 清朝早期(到鸦片战争前)

   敏感话题(中立陈述,不带价值判断)
   ──────────────────────────────────────────
   ⚠ 元朝对汉人的统治政策
   ⚠ 清朝边疆民族政策
   ⚠ 满汉关系
   ⚠ 鸦片战争 - 八国联军
   ⚠ 任何涉及"民族主义" / "汉本位"的内容

   红线话题(简短陈述事件 + 时间,不做"为什么"解释)
   ──────────────────────────────────────────
   ✗ 国共关系细节
   ✗ 西藏 / 新疆 / 台湾历史细节
   ✗ 文革(若 Phase 1 不推迟到 1976 后)

   1949-1976 范围内整体推迟到 Phase 后期决定是否覆盖
```

## 图片处理

### 来源优先级

```
   1. Wikimedia Commons   ← CC-BY-SA / CC0 / Public Domain
                            ✓ 真实文物图、传统画像
                            ✓ 公开仓库**无版权风险**
                            → β scope 80%+ 内容靠这里

   2. zh.wikipedia.org    ← 同上协议
                            ✓ 主条目首图

   3. 故宫博物院 / 国博官网 ← 高清但有版权声明
                            ✗ 公开仓库**不放**,本地 review 用

   4. 百度百科             ← 来源混乱,版权不明
                            ✗ 公开仓库**不放**

   5. AI 生成              ← Midjourney / SD
                            ⚠ 历史人物像不可信(孔子长什么样?)
                            → Phase 1 不用
```

### Phase 1 图片 scope

```
   必做:    25 朝代 hero 图(每朝代 1 张,~5 MB 总量)
   可做:    β 时段 ~50 关键人物 portrait
   不做:    事件场景图(Phase 2 评估)
```

### 爬取工作流

```
   tools/crawl_images.py (基于 Scrapling)
        │
        ├── 输入: dynasties.json + persons.json 关键词
        ├── 数据源: 仅限 Wikimedia Commons + Wikipedia
        ├── 输出: raw/images/<entity>/<id>/*.{jpg,png}
        │       (每实体 5-20 张候选)
        ▼
   ┌──────────────────────────────────────────┐
   │  人工筛选(瓶颈)                           │
   │  你看一遍选最好的 1 张                    │
   │  ~30 秒/张 × 75 实体 × 平均 8 候选         │
   │  = ~5 小时(β scope)                       │
   └──────────────────────────────────────────┘
        ▼
   tools/process_images.py (Pillow + WebP)
        │
        ├── 压缩到 800x600 webp,~150 KB
        ├── 缩略图 320x240 webp,~30 KB
        └── 输出: data_source/images/<entity_type>/<id>.{webp,thumb.webp}
        ▼
   tools/build.py 把 data_source/images → assets/images/
   tools/build_image_manifest.py 生成图片 manifest(供热更检测)
```

### 自动评分(降低人工筛选成本)

爬下来的候选图按以下规则自动 rank:
- 分辨率 ≥ 800x600 加分
- 来源 commons.wikimedia.org 加分(权威)
- 文件名含人物 / 事件名加分
- 标签含"painting" / "statue" / "portrait" 加分
- 自动选 top1 默认采用,但你可以一键切换备选

## 写作工作流(β 深耕实操)

```
   Day 1: 列事件清单
   ───────────────────────────────────────
   1. LLM(DeepSeek-V3)给每朝代列 100 件
   2. 你 review,删 / 加 / 改名,确定 60-90 件
   3. 落到 data_source/seed/phase1_events.yaml

   Day 2-3: summary 起草 + 校对
   ───────────────────────────────────────
   1. LLM 批量给每条事件出 200-300 字 A 风格 summary
   2. 你 review,主要校对"年份/地点/人名"
   3. ~20 秒/条,90 条 ~30 分钟

   Day 4-7: body 起草 + 校对
   ───────────────────────────────────────
   1. LLM 批量给每条事件出 1500 字 C 风格 body
   2. 你 review,重点校"故事顺序 + 现代视角是否站得住"
   3. ~5-7 分钟/条,90 条 ~10 小时

   Day 8: 图片爬 + 筛
   ───────────────────────────────────────
   1. tools/crawl_images.py 跑一晚
   2. 你筛选 ~5 小时

   Day 9-10: validate + build + 真机测试
```

总计 ~10 个工作日(全职),~3-4 周末(业余)。

## 反例集合(写作时避开)

```
   ✗ "那是个寒冷的清晨,武王站在战车上..."
     → 编造细节,史书无记载

   ✗ "武王伐纣是中国历史上最重要的战役"
     → 主观最高级评价

   ✗ "纣王这个昏庸的暴君..."
     → 价值判断,且打脸现代视角

   ✗ "据说当时..."
     → 不确定的传闻,要么写明"史书载",要么不写

   ✗ "小编认为..." / "值得一提的是..."
     → 口语化,不专业

   ✓ "公元前 1046 年正月,武王集结诸侯联军,从孟津渡河"
     → 时间 / 事件 / 地点,精确

   ✓ "现代史学家认为,周联军能赢更多是商朝长期内耗"
     → 明确"现代史学家",而非"我认为"
```
